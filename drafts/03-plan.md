## 读者和产品边界

第一读者是准备设计 Agent/Harness 的独立开发者，以及已经熟悉 Agent 架构、希望研究 DeepSeek 设计取舍的人。成品是一篇 60–90 分钟的中文长文，配一张可探索的架构总图和一个无密钥实验。

MVP 深挖六个系统：

1. Cordis 运行时
2. Profile / Bundle 装配
3. Agent Scope
4. Agent Loop
5. Session Event Log
6. Tool / LLM Capability

Web、ACP、Python SDK、Typert RPC 和其他外围表面进入全景图，只解释职责和连接关系。

## 证据等级

- 已证实：源码、测试、提交说明、Agent Note 或官方文档直接支持。
- 合理推断：连续 diff、删除行为或多个独立证据共同支持，但作者没有明说。
- 仍然未知：仓库材料不足，不能替作者补写动机。

每个关键结论至少记录文件路径与行号，历史判断再附 commit hash。正文默认隐藏长证据，证据库保留完整索引。

## 覆盖率目标

- 六个核心系统：选定核心文件最低阅读覆盖率 90%。
- 外围模块：选定文件最低阅读覆盖率 60%。
- 超大生成文件、测试快照和纯 UI 组件不计入核心覆盖率，记录排除理由。

覆盖率表示“实际读过的选定关键文件范围”，不是占仓库全部 23 万行的比例。最终另写汇总表，避免用一个虚高的全仓数字掩盖核心盲区。

## 协作与审查

每个子 Agent 只负责一个独立领域，草稿必须遵循 `humanizer-zh`：少用宣传词、三段式排比和空泛结论，直接写证据、判断和不确定性。

每份子 Agent 草稿完成后，都交给另一个对抗性审查 Agent。审查至少检查：

- 引用的路径、行号和 commit 是否真的支持结论；
- 是否把推断写成事实；
- 是否漏掉反例、回滚或替代解释；
- 是否按目录流水账，而没有解释边界和权衡；
- 是否存在 AI 腔、模板化小标题或不必要的夸张。

原作者根据审查意见修订，主 Agent 最后再抽查关键结论。
