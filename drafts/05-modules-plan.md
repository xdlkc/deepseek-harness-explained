# 模块与叙事计划

## 主叙事

读者先看到今天的系统，再沿着一次请求走进内部。每遇到一个看似多余的抽象，就回到提交史寻找它解决过的问题。

`Profile / Bundle` 组装插件树
→ `[插件需要可撤销的生命周期与隔离]`
→ `Cordis Context / Fiber / Loader`
→ `[同一运行时要为每个 Agent 提供不同能力世界]`
→ `Agent Scope`
→ `[作用域装好能力后，需要一个很薄的执行协调者]`
→ `Agent Loop`
→ `[执行过程不能只活在内存里]`
→ `Session Event Log`
→ `[模型和工具都要通过稳定边界接入]`
→ `Tool / LLM Capability`

历史演进不单独堆成年表。每个当前设计讲清后，再插入它的前身、失败方案和删除记录。最后集中串起十条主线，让读者看到这两个月究竟删掉了什么。

## 章节骨架

1. 先给答案：这是什么 Harness
2. 一张图看懂当前系统
3. 从 `dsh` 命令到插件树
4. Cordis：为什么插件卸载比插件加载更难
5. 每个 Agent 都有自己的运行时世界
6. 一次模型请求怎样穿过 Agent Loop
7. Session Log：模型看到的东西必须能重建
8. Tool 与 LLM：能力为什么拆成三种角色
9. 十条设计演进线
10. 文档如何成为工程约束
11. 无密钥实验：重放一次请求
12. 我的评价与仍然不知道的事

## 阅读降负规则

- 每章开头先给 3–5 条结论。
- 先图后文，一个段落只说一个主要意思。
- 术语首次出现时用白话解释，保留英文原词。
- 长源码、diff 和证据默认折叠。
- 每章结尾说明“读到这里应该明白什么”。
- 允许从架构图跳到任意章节，不强迫线性阅读。
