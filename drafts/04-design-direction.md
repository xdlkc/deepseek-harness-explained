# 展示设计方向

## 第一稿：运行时剖面图

### 页面任务

这页只做一件事：让准备设计 Harness 的开发者，在不被 23 万行源码淹没的前提下，看懂 DeepSeek Harness 的运行时结构和设计来路。

### 色彩

| 名称 | 色值 | 用途 |
|---|---|---|
| 雾灰 | `#eef3f8` | 文章专属浅色背景 |
| 深墨 | `#172033` | 正文和主轮廓 |
| Cordis 蓝 | `#2563eb` | 运行时组合与生命周期 |
| Session 琥珀 | `#b45309` | 持久事件与证据链 |
| Scope 紫 | `#6d28d9` | 作用域和遮蔽关系 |
| 边界灰 | `#9aa8ba` | 外围系统和次要连线 |

深色模式不简单反相。背景改成蓝灰黑，三个系统色降低亮度和饱和度，避免代码编辑器式荧光。

### 字体

- 正文：`PingFang SC, Noto Sans SC, system-ui, sans-serif`
- 标题：沿用正文族，但提高字宽、减少字重；中文长文不额外下载展示字体
- 证据、commit、事件序号：`SFMono-Regular, Consolas, Liberation Mono, monospace`

个性不靠生僻字体。commit hash、事件序号和路径排版承担“技术档案”的识别度，也避免中文读者遇到字体闪烁或境内字体 CDN 失败。

### 标志性元素

同一张架构图有两个可切换的观察平面：

- “运行时”只显示 Cordis、Profile/Bundle、Scope、Agent Loop 和 Capability 的装配关系。
- “持久事实”压暗运行时连线，显示 Session Event 如何驱动恢复、投影和模型上下文。

这个切换不是装饰。它把文章最重要的判断直接做成交互：DeepSeek Harness 有两套互相咬合、职责不同的内核。

## 自我批评与修订

第一稿容易落入“深色技术蓝图”的常见模板。修订如下：

- 不使用满屏网格、扫描线或发光边框。主体仍是博客的浅色阅读环境。
- 不给六个模块做六张同款圆角卡片。模块形状编码职责：装配层是层叠片，作用域是嵌套框，循环是路径，Session 是事件带。
- 动画只保留一次：切换观察平面时重排连线。滚动过程中不让节点反复飞入。
- 演进史用 Session Log 的 `seq` 视觉语法排版，而不是另做一条常见的营销时间线。commit hash 是证据入口，不是装饰编号。
- 文章关闭 JavaScript 后仍显示完整静态图和正文；交互只是减少认知负担。

最终方向叫“运行时剖面图”，不是“未来感控制台”。读者来这里是为了理解系统，不是看作品集动画。
